# Bulls and Cows: проектная документация

Игра написана на TypeScript, без классов и без сторонних библиотек для логики. Вся игровая логика состоит из чистых функций и не зависит от DOM, поэтому тестируется без браузера.

**Поток данных.** Действие пользователя попадает в обработчик в `src/main.ts`. Обработчик вызывает чистую функцию из `src/game` (например, `submitGuess`), получает новое состояние, сохраняет его в единственную переменную `state` и перерисовывает экран. Старое состояние при этом не меняется.

## Структура проекта

| Папка          | Что внутри                                                                                       | Побочные эффекты        |
| -------------- | ------------------------------------------------------------------------------------------------ | ----------------------- |
| `src/game`     | Игровая логика: валидация, секрет, подсчёт bulls/cows, состояние, рекорды, клавиатура, настройки | Нет                     |
| `src/utils`    | Общие помощники: `memoize`, `parseTheme`                                                         | Нет                     |
| `src/services` | Работа с `localStorage` (`storage.ts`)                                                           | Да, единственное место  |
| `src/ui`       | Построение DOM через `h()` (`createElement`, без `innerHTML`)                                    | DOM                     |
| `src/main.ts`  | Склейка: единственная изменяемая переменная `state`, обработчики, перерисовка                    | DOM, время, случайность |

Тесты лежат рядом с кодом (`*.test.ts`) и не попадают в сборку (`tsconfig.build.json`).

## 1. Структуры данных и алгоритмы

### Состояние игры (`src/game/state.ts`)

```ts
type GameState = {
  settings: { length: number; base: number };
  secret: string;
  status: 'playing' | 'won';
  history: readonly Attempt[]; // Attempt = { guess, bulls, cows }
  startedAt: number;
  finishedAt: number | null;
};
```

- **Обычный объект, а не класс.** Состояние обновляется копированием (`{ ...state, ... }`), поэтому старое состояние никогда не меняется. Это проверяется тестом с `Object.freeze` (`state.test.ts`).
- **История это массив только на добавление.** Порядок попыток важен, их количество заранее неизвестно (лимита нет, но обычно это единицы или десятки), а список отрисовывается по порядку. Новая попытка добавляется как `[...state.history, entry]`. Старые записи при этом не копируются, а переиспользуются по ссылке, поэтому копируется только массив ссылок. Более сложные структуры (связный список, persistent vector) для такого объёма не окупаются.
- **Время и случайность приходят параметрами.** `createGame(settings, secret, now)` и `submitGuess(state, guess, now)` не вызывают `Date.now()` и `Math.random()`, поэтому функции чистые, а тесты детерминированные.
- **Раунд это `GameState | null` в `main.ts`.** `null` означает экран настроек. Блокировка настроек получается сама: они заблокированы, пока состояние не `null`.
- **`finishedAt: number | null`** вместо отдельного флага: время остановки хранится там же, где факт победы. `getElapsedMs` после победы возвращает `finishedAt - startedAt` и не зависит от текущего времени.

### Система счисления и длина секрета (`src/game/settings.ts`, `src/game/validator.ts`)

- **Один алфавит: строка `DIGITS = '0123456789abcdef'`.** Для системы с основанием `base` допустимы её первые `base` символов (`DIGITS.slice(0, base)`). Клавиатура, генератор секрета и валидатор берут алфавит из одного места.
- **Длина 2–6** задаётся константами `MIN_LENGTH` и `MAX_LENGTH`. Доступные длины для системы счисления это те, что не превышают `base` (`getAvailableLengths`): для двоичной системы остаётся только 2.
- **`withBase(settings, base)`** возвращает новые настройки: при смене системы длина сохраняется, если она допустима, иначе берётся наименьшая допустимая. Правило живёт в одной чистой функции, а не размазано по обработчикам интерфейса.

### Секрет и попытки (`src/game/validator.ts`)

- **Секрет и попытки это строки**, а не числа, чтобы не терять ведущие нули (`0123`). Для hex все цифры приводятся к нижнему регистру.
- **`Set`** используется в `isValidGuess` (поиск повторов: размер множества меньше длины, значит, есть повтор) и в `evaluateGuess` (быстрая проверка «эта цифра есть в секрете»). Проверка принадлежности занимает O(1) в среднем вместо O(n) у `includes`.

### Кеш мемоизации (`src/utils/memoize.ts`)

`Map<string, Result>`, ключ это `JSON.stringify(args)`. Запятые и скобки отделяют аргументы друг от друга, поэтому пары `(1, 12)` и `(11, 2)` не сливаются в один ключ. Наличие результата проверяется через `cache.has`, а не по «истинности» значения, поэтому закешированные `0`, `false` и `''` не пересчитываются.

### Рекорды (`src/game/records.ts`)

Плоский массив `GameRecord[]` вида `{ settings, attempts, timeMs }`. Для каждой комбинации «длина и система счисления» ведётся отдельный топ (`TOP_LIMIT = 10`), потому что сравнивать 2 попытки в двоичной системе с 6 в hex нечестно. Порядок: меньше попыток, при равенстве меньше времени. Плоский массив сериализуется в одну строку JSON для `localStorage`. При чтении `parseRecords` не доверяет хранилищу: битый JSON, не массив и испорченные записи отбрасываются, а допустимые остаются.

### Алгоритм `isValidGuess` (`src/game/validator.ts`)

Попытка допустима, если одновременно верны три условия: длина совпадает с заданной, каждый символ принадлежит алфавиту системы (проверяет каррированный предикат `createDigitValidator(base)`) и цифры не повторяются (размер `Set` равен длине). Регистр hex не учитывается.

### Алгоритм `evaluateGuess` (`src/game/evaluate.ts`)

Секрет и попытка не содержат повторяющихся цифр, поэтому подсчёт сводится к двум числам:

1. `bulls`: сколько цифр попытки совпали с секретом на той же позиции (`filter` по индексу).
2. `common`: сколько цифр попытки вообще есть в секрете (`filter` и `Set` секрета).
3. `cows = common - bulls`: цифры, которые есть в секрете, но стоят не на своём месте.

Из-за уникальности цифр каждая цифра попадает ровно в одну из категорий, поэтому вычитание корректно. Всё сделано методами массивов, без ручных циклов и счётчиков, регистр приводится к нижнему через `toLowerCase`.

Пример: секрет `4271`, попытка `4723`. На месте совпадает только `4`, то есть bulls = 1. Цифры `4`, `7` и `2` есть в секрете, значит common = 3, и cows = 3 − 1 = 2.

### Алгоритм `countPossibleSecrets` (`src/game/count.ts`)

Число различных секретов это число размещений без повторений P(base, length) = base · (base − 1) · … · (base − length + 1). Первая цифра может быть любой (в том числе 0), поэтому отдельного вычитания нет. Рекуррентная формула:

```
f(0, b) = 1
f(l, b) = 0                    при l > b
f(l, b) = b * f(l - 1, b - 1)  иначе
```

Пример: для десятичной системы и длины 3 получаем 10 · 9 · 8 = 720.

Функция реализована рекурсивно и обёрнута в `memoize`. Рекурсивный вызов идёт через уже мемоизированную версию, поэтому кеш используется на всех уровнях. Выигрыш мемоизации не в самом вычислении (подзадачи одной цепочки не повторяются), а в повторных вызовах: экран настроек пересчитывает значение при каждом изменении, и теперь это поиск в `Map`.

### Алгоритм `generateSecret` (`src/game/secret.ts`)

Выбор без возвращения: на каждом шаге из оставшихся цифр берётся одна по индексу `floor(random() * pool.length)`, затем она удаляется из пула (`filter`), и функция вызывает себя для остатка. Каждый шаг равновероятен, поэтому любая упорядоченная выборка получается с вероятностью 1 / P(base, length). Источник случайности (`random`) передаётся параметром, поэтому в тестах подставляется детерминированный. Если `length > base`, функция бросает `RangeError`, а не возвращает `undefined` вместо цифры.

## 2. Сложность

Обозначения: `n` это длина секрета или попытки (в игре 2–6), `b` это основание системы счисления (в игре 2, 8, 10 или 16).

| Функция                | Время                                      | Память          |
| ---------------------- | ------------------------------------------ | --------------- |
| `generateSecret`       | O(n · b)                                   | O(n · b)        |
| `evaluateGuess`        | O(n)                                       | O(n)            |
| `isValidGuess`         | O(n · b)                                   | O(n + b)        |
| `countPossibleSecrets` | O(n) при первом вызове, O(1) при повторном | O(n) стек и кеш |

**`generateSecret`.** Рекурсия делает `n` шагов. На каждом шаге один вызов `random()` и один `filter` по оставшимся цифрам (не больше `b` элементов), то есть O(b). Склейка результата через spread даёт дополнительно O(n) на шаг, всего O(n²), но так как `n ≤ b`, это входит в O(n · b). Память: каждый уровень рекурсии держит свой уменьшенный пул, поэтому до O(n · b).

**`evaluateGuess`.** Две строки по `n` символов превращаются в массивы за O(n). Множество секрета строится за O(n). Два прохода `filter` по `n` элементам, каждая проверка принадлежности множеству занимает O(1) в среднем. Итого O(n). Если бы вместо `Set` использовался `includes`, получилось бы O(n²).

**`isValidGuess`.** Создание валидатора копирует алфавит за O(b). Разбиение строки и `map` занимают O(n). `every(isDigit)` делает до `n` проверок, и каждая это поиск символа в строке-алфавите за O(b), итого O(n · b). Поиск повторов через `Set` занимает O(n). Общая сложность O(n · b). Так как `b ≤ 16` и `n ≤ 6`, на практике это константа. При большом алфавите поиск заменили бы на `Set` и получили бы O(n + b).

**`countPossibleSecrets`.** Первый вызов делает `n + 1` вызовов рекурсии по O(1) каждый, глубина стека O(n). Рекурсия останавливается на `length = 0` (результат 1) или на `length > base` (результат 0). Повторный вызов с теми же аргументами берётся из кеша: ключ строится из двух чисел, поэтому поиск стоит O(1). Размер кеша ограничен числом различных пар `(length, base)`, достижимых из настроек игры, это несколько десятков записей.

## Тестирование

Каждая обязательная функция написана по TDD: сначала коммит с падающими тестами, затем коммит с реализацией. Тесты следуют FIRST: быстрые (нет ввода-вывода и таймеров), независимые (каждый тест создаёт свои данные), повторяемые (случайность и время подставляются снаружи; единственный тест без подстановки, `generateSecret` с `Math.random` по умолчанию, проверяет только структуру результата), самопроверяющиеся (только `expect`), написаны до реализации. Порядок коммитов виден во вкладке Commits pull request.
